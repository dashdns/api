# API Contract — policy-controller

The HTTP contract for client-side work (dashboard / CLI). Derived from
`internal/*/module.go`, `internal/httpx`, `internal/auth`, and `pkg/dnsdcontract`.

- **Base URL (API):** `http://<host>:8080` (`-listen`, defaults to `:8080`)
- **Metrics (separate listener):** `http://<host>:9091/metrics` (`-metrics-listen`) — **not** on the API port.
- **Content type:** Request and response bodies are `application/json`.
- **Date format:** RFC 3339 / UTC (`2026-08-29T10:11:12Z`).

---

## 1. Two separate credential planes

| Plane | Token format | Where it comes from | Which endpoints |
|---|---|---|---|
| **Appliance** (dnsd) | `dnsdap_<16 hex>_<43 char base64url>` | Response of `POST /api/admin/appliances` or `.../rotate` | Only `GET /api/policies` |
| **Admin** (dashboard) | `dnsdsn_<16 hex>_<43 char base64url>` | `POST /api/admin/auth/login` | All of `/api/admin/*` |

The two are **not** interchangeable. An admin token sent to `/api/policies`, or an
appliance token sent to `/api/admin/*`, returns `401`.

Both are sent with the same header:

```
Authorization: Bearer dnsdsn_9f2c1a0b7e4d3562_kQ7x...
```

## 2. Header reference

### Request headers

| Header | Required | Where | Notes |
|---|---|---|---|
| `Authorization: Bearer <token>` | Yes (except login and ops) | All protected endpoints | Scheme is case-insensitive (`bearer` works too). |
| `Content-Type: application/json` | On requests with a body | POST / PUT / PATCH | May be omitted; a **wrong** value yields `415`. Accepted: `application/json`, `text/json`, `application/json; charset=utf-8`. |
| `X-Tenant-ID: <tenant>` | No | `/api/admin/*` | Only meaningful in **multi-tenant** mode and only for `superadmin`: acts on behalf of another tenant. A value outside your own tenant with the `admin` role ⇒ `403`. Ignored entirely in single-tenant mode. |
| `X-Request-ID: <=64 chars` | No | All | Correlation ID. Generated by the server if absent; echoed back either way. |
| `If-None-Match: "<etag>"` | No | `GET /api/policies` | Returns `304` on a match. |
| `If-Modified-Since: <HTTP-date>` | No | `GET /api/policies` | Only considered when `If-None-Match` is **absent** (RFC 9110 §13.1.3). |

### Response headers

| Header | Where |
|---|---|
| `Content-Type: application/json; charset=utf-8` | All responses with a body |
| `X-Request-ID` | All responses |
| `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` | All responses |
| `Location: /api/admin/<...>` | `201 Created` responses (policy, appliance, tenant) |
| `WWW-Authenticate: Bearer realm="dnsd-admin"\|"dnsd-appliance", error="invalid_token"` | `401` |
| `ETag`, `Last-Modified`, `Cache-Control: private, no-cache`, `Vary: Authorization`, `X-Policy-Revision` | `GET /api/policies` (both 200 and 304) |

## 3. Common error body

Every error has a single shape:

```json
{
  "error": "bad_request",
  "message": "invalid domains",
  "details": { "domains": "domain \"exa mple.com\" must be a bare hostname with no path, port or whitespace" }
}
```

`details` is present only for field-level validation errors.

| `error` code | HTTP | When |
|---|---|---|
| `bad_request` | 400 | Validation failure, malformed JSON, empty body, unknown field |
| `unauthorized` | 401 | Token missing / invalid / expired / revoked |
| `forbidden` | 403 | `superadmin` required, or `X-Tenant-ID` not permitted |
| `not_found` | 404 | No such record or route |
| `conflict` | 409 | Record already exists, or an attempt to delete the default tenant |
| `unsupported` | 415 | `Content-Type` is not JSON |
| `payload_too_large` | 413 | Body larger than 1 MiB |
| `internal_error` | 500 | Server-side failure |

**JSON decode rules (important for clients):** a request carrying an **unknown field**
is rejected with `400` (`DisallowUnknownFields`), the body must be a single JSON object,
and it is capped at 1 MiB.

## 5. Ops endpoints (no auth)

### 5.1 `GET /` — route index

```http
GET / HTTP/1.1
```

`200 OK`

```json
{
  "service": "policy-controller",
  "version": "1.0.0",
  "mode": "single-tenant",
  "routes": [
    { "method": "GET", "pattern": "/api/admin/appliances", "module": "appliances" },
    { "method": "POST", "pattern": "/api/admin/auth/login", "module": "identity" }
  ]
}
```

`mode`: `"single-tenant"` | `"multi-tenant"`. A client can read this at startup to show
or hide the tenant screens.

Every unmatched path also lands on this handler and gets a `404`:

```json
{ "error": "not_found", "message": "no route for GET /api/foo" }
```

### 5.2 `GET /healthz` — liveness (never touches the DB)

`200 OK`

```json
{ "status": "ok", "version": "1.0.0", "mode": "single-tenant", "uptime_seconds": 4211 }
```

### 5.3 `GET /readyz` — readiness (DB ping)

`200 OK` → `{ "status": "ready" }`

`503 Service Unavailable` → `{ "status": "unavailable", "reason": "database unreachable" }`

## 6. Appliance plane

### 6.1 `GET /api/policies` — dnsd blocklist

This payload is a **frozen** contract (`pkg/dnsdcontract`); no field may be added or
removed.

**Headers**

```
Authorization: Bearer dnsdap_3c1f9b2a7d0e4685_yT8...
If-None-Match: "6f1a9c2b4d3e5081"        # optional
```

`200 OK`

```
ETag: "6f1a9c2b4d3e5081"
Last-Modified: Fri, 29 Aug 2026 09:12:44 GMT
Cache-Control: private, no-cache
Vary: Authorization
X-Policy-Revision: 42
```

```json
{
  "blocklist": [
    { "ip": "192.168.1.10", "domains": ["ads.example.com", "tracker.example.net"] },
    { "ip": "192.168.1.11", "domains": ["facebook.com"] }
  ]
}
```

With no policies you get `{"blocklist":[]}` — never `null`.

`304 Not Modified` — no body; `ETag`, `Last-Modified`, `Cache-Control` and `Vary` are
still sent.

`HEAD` is supported as well (same headers, no body).

`401 Unauthorized`

```
WWW-Authenticate: Bearer realm="dnsd-appliance", error="invalid_token"
```

```json
{
  "error": "unauthorized",
  "message": "appliance authentication failed (revoked); send Authorization: Bearer <appliance token>"
}
```

The reason in parentheses is one of: `missing` | `invalid` | `revoked` | `expired`.

> On a deployment running with `-require-appliance-auth=false`, a request that sends
> **no token at all** falls through as anonymous against the default tenant and gets a
> `200`. A token that *is* presented is always verified.

## 7. Admin — identity

### 7.1 `POST /api/admin/auth/login`

**Headers:** `Content-Type: application/json` (no auth)

**Request**

```json
{ "username": "admin", "password": "correct-horse-battery" }
```

`200 OK`

```json
{
  "token": "dnsdsn_9f2c1a0b7e4d3562_kQ7xJ2mR8vT4pL0nZ6yB1cF3dS5wA9gH2jK4lM6nP8Q",
  "expires_at": "2026-08-29T22:11:04Z",
  "expires_in_seconds": 43200,
  "principal": {
    "kind": "admin",
    "id": "usr_4c8f21b6d9e07a3518f2ba64c7d90e15",
    "username": "admin",
    "tenant_id": "default",
    "role": "superadmin"
  }
}
```

`token` goes on every subsequent admin call as `Authorization: Bearer <token>`. Default
lifetime is 12 hours (`-admin-session-ttl`).

**Errors**

- `400` — empty username/password:
  ```json
  { "error": "bad_request", "message": "username and password are required",
    "details": { "username": "required", "password": "required" } }
  ```
- `401` — `{ "error": "unauthorized", "message": "invalid username or password" }`
  ("no such user" and "wrong password" are **deliberately** indistinguishable)

### 7.2 `POST /api/admin/auth/logout`

**Headers:** `Authorization: Bearer <session token>`

`204 No Content` (no body). It is idempotent: an unknown or malformed token also returns
`204`.

### 7.3 `GET /api/admin/auth/whoami`

**Headers:** `Authorization: Bearer <session token>`

`200 OK`

```json
{
  "kind": "admin",
  "id": "usr_4c8f21b6d9e07a3518f2ba64c7d90e15",
  "username": "admin",
  "tenant_id": "default",
  "role": "superadmin"
}
```

`kind`: `admin` | `appliance`. `role`: `admin` | `superadmin`.

`401` (expired session):

```json
{
  "error": "unauthorized",
  "message": "admin authentication failed (expired); log in at POST /api/admin/auth/login"
}
```

## 8. Admin — policies

The shared `View` shape:

```json
{
  "id": "pol_7b3e9d1c5a2f48609e8d7c6b5a4f3e2d",
  "tenant_id": "default",
  "ip": "192.168.1.10",
  "domains": ["ads.example.com", "tracker.example.net"],
  "created_at": "2026-08-20T08:00:00Z",
  "updated_at": "2026-08-29T09:12:44Z"
}
```

**Validation rules (worth mirroring client-side):**

- `ip`: **IPv4 dotted-quad only**. IPv6, IPv4-mapped (`::ffff:1.2.3.4`) and zone-ID
  addresses are rejected — dnsd's BPF map is keyed on IPv4.
- `domains[]`: bare hostnames. Lowercased, trailing `.` stripped, duplicates dropped and
  **sorted alphabetically** (which is why the order you get back is not the order you
  sent). Rejected: a scheme (`https://`), path/port/whitespace (`/?#@`), wildcards (`*`),
  empty labels (`..`), non-ASCII characters (send the punycode `xn--` form).
- Limits: domain ≤ 253, label ≤ 63, at most 4096 domains per policy.

### 8.1 `GET /api/admin/policies`

**Headers:** `Authorization: Bearer <session>`, optional `X-Tenant-ID`

`200 OK`

```json
{
  "policies": [ { "id": "pol_...", "tenant_id": "default", "ip": "192.168.1.10",
                  "domains": ["ads.example.com"], "created_at": "2026-08-20T08:00:00Z",
                  "updated_at": "2026-08-29T09:12:44Z" } ],
  "count": 1,
  "revision": 42
}
```

`revision` is the tenant's policy counter — the same counter behind `X-Policy-Revision`
on `GET /api/policies`, so a dashboard can use it to show whether appliances are current.

### 8.2 `POST /api/admin/policies`

**Headers:** `Authorization`, `Content-Type: application/json`, optional `X-Tenant-ID`

**Request**

```json
{ "ip": "192.168.1.10", "domains": ["Ads.Example.com.", "tracker.example.net", "ads.example.com"] }
```

`201 Created`

```
Location: /api/admin/policies/192.168.1.10
```

```json
{
  "id": "pol_7b3e9d1c5a2f48609e8d7c6b5a4f3e2d",
  "tenant_id": "default",
  "ip": "192.168.1.10",
  "domains": ["ads.example.com", "tracker.example.net"],
  "created_at": "2026-08-29T09:12:44Z",
  "updated_at": "2026-08-29T09:12:44Z"
}
```

(The three domains in the request normalized down to two.)

**Errors**

- `400` — empty `domains`: `{"error":"bad_request","message":"a new policy must list at least one domain","details":{"domains":"must not be empty"}}`
- `400` — invalid IP: `{"error":"bad_request","message":"invalid ip","details":{"ip":"\"10.0.0.500\" is not a valid IP address"}}`
- `404` — (multi-tenant) `X-Tenant-ID` names an unknown tenant: `{"error":"not_found","message":"unknown tenant \"acme\""}`
- `409` — `{"error":"conflict","message":"a policy for 192.168.1.10 already exists; use PUT or PATCH to modify it"}`

### 8.3 `GET /api/admin/policies/{ip}`

`200 OK` → a single `View`.
`404` → `{"error":"not_found","message":"no policy for 192.168.1.10"}`

### 8.4 `PUT /api/admin/policies/{ip}` — full replacement (upsert)

**Request** (`ip` is optional; if present it must match the path)

```json
{ "ip": "192.168.1.10", "domains": ["only-this.example.com"] }
```

`200 OK` → the updated `View`.

Sending `domains: []` **empties** the policy (it does not delete it). If the record does
not exist, it is created.

`400` — path/body mismatch:

```json
{ "error": "bad_request", "message": "body ip \"192.168.1.11\" does not match path ip \"192.168.1.10\"" }
```

### 8.5 `PATCH /api/admin/policies/{ip}` — partial change

**Request** (at least one of `add` / `remove` must be non-empty)

```json
{ "add": ["newsite.example.org"], "remove": ["tracker.example.net"] }
```

`200 OK` → the updated `View`.

- `400` — both empty: `{"error":"bad_request","message":"nothing to do","details":{"add":"at least one of add or remove must be non-empty"}}`
- `404` — no such policy (PATCH does not create)

### 8.6 `DELETE /api/admin/policies/{ip}`

`204 No Content` · `404` if the record does not exist.

## 9. Admin — appliances

The appliance `View` (**never** carries a token):

```json
{
  "id": "app_1a2b3c4d5e6f708192a3b4c5d6e7f809",
  "tenant_id": "default",
  "name": "branch-office-01",
  "description": "Istanbul HQ edge",
  "token_id": "3c1f9b2a7d0e4685",
  "revoked": false,
  "created_at": "2026-08-20T08:00:00Z",
  "last_seen_at": "2026-08-29T09:10:02Z",
  "revoked_at": null
}
```

`description`, `last_seen_at` and `revoked_at` are **omitted entirely** when empty
(`omitempty`) — clients must treat them as optional.

> **The token appears exactly once, in the create and rotate responses.** The server
> stores only its SHA-256; a lost token cannot be recovered, only rotated. The UI should
> treat this as a "copy it now" flow.

### 9.1 `GET /api/admin/appliances`

`200 OK`

```json
{ "appliances": [ { "id": "app_...", "name": "branch-office-01", "revoked": false } ], "count": 1 }
```

### 9.2 `POST /api/admin/appliances`

**Headers:** `Authorization`, `Content-Type: application/json`, optional `X-Tenant-ID`

**Request** (`name`: 1–128 characters; `description` optional)

```json
{ "name": "branch-office-01", "description": "Istanbul HQ edge" }
```

`201 Created`

```
Location: /api/admin/appliances/app_1a2b3c4d5e6f708192a3b4c5d6e7f809
```

```json
{
  "appliance": {
    "id": "app_1a2b3c4d5e6f708192a3b4c5d6e7f809",
    "tenant_id": "default",
    "name": "branch-office-01",
    "description": "Istanbul HQ edge",
    "token_id": "3c1f9b2a7d0e4685",
    "revoked": false,
    "created_at": "2026-08-29T09:12:44Z"
  },
  "token": "dnsdap_3c1f9b2a7d0e4685_yT8kR2mQ7vX4pN0zL6bY1cF3dS5wA9gH2jK4lM6nP8Q",
  "hint": "Store this token now; it cannot be retrieved again. Pass it to dnsd with -ip-blocklist-token (or DNSD_IP_BLOCKLIST_TOKEN)."
}
```

**Errors**

- `400` — `{"error":"bad_request","message":"invalid appliance name","details":{"name":"must be 1-128 characters"}}`
- `409` — `{"error":"conflict","message":"an appliance named \"branch-office-01\" already exists in this tenant"}`

### 9.3 `POST /api/admin/appliances/{id}/rotate`

No body. Mints a new token **and clears any revocation** — this is how a revoked
appliance is brought back into service.

`200 OK` → the same `{appliance, token, hint}` shape as 9.2.

`404` → `{"error":"not_found","message":"no such appliance"}`

### 9.4 `POST /api/admin/appliances/{id}/revoke`

No body. Does not delete the record; it invalidates the token (the audit trail and
`last_seen_at` survive). Idempotent.

`200 OK`

```json
{
  "id": "app_1a2b3c4d5e6f708192a3b4c5d6e7f809",
  "tenant_id": "default",
  "name": "branch-office-01",
  "token_id": "3c1f9b2a7d0e4685",
  "revoked": true,
  "created_at": "2026-08-20T08:00:00Z",
  "last_seen_at": "2026-08-29T09:10:02Z",
  "revoked_at": "2026-08-29T09:20:00Z"
}
```

### 9.5 `GET /api/admin/appliances/{id}` · `DELETE /api/admin/appliances/{id}`

`GET` → `200` + `View`. `DELETE` → `204 No Content`. Both return `404` if absent.

## 10. Admin — tenants (multi-tenant mode only, superadmin)

The tenant shape:

```json
{
  "id": "acme",
  "name": "ACME Corp",
  "created_at": "2026-08-20T08:00:00Z",
  "updated_at": "2026-08-20T08:00:00Z"
}
```

Called with the `admin` role, all of these return `403`:

```json
{ "error": "forbidden", "message": "this endpoint requires the superadmin role" }
```

### 10.1 `GET /api/admin/tenants`

`200 OK` → `{ "tenants": [ { "id": "acme", "name": "ACME Corp", ... } ], "count": 1 }`

### 10.2 `POST /api/admin/tenants`

**Request** (if `name` is empty, `id` is used)

```json
{ "id": "acme", "name": "ACME Corp" }
```

`201 Created` + `Location: /api/admin/tenants/acme` → the tenant object.

`id` rules: lowercase letters, digits and `-`, at most 63 characters, may not start or
end with `-`.

- `400` — `{"error":"bad_request","message":"invalid tenant id","details":{"id":"must contain only lowercase letters, digits and '-'"}}`
- `409` — `{"error":"conflict","message":"tenant \"acme\" already exists"}`

### 10.3 `GET /api/admin/tenants/{id}` · `DELETE /api/admin/tenants/{id}`

`GET` → `200` + tenant. `DELETE` → `204`; the tenant's policies, appliances and admins
are **cascade-deleted**.

- `404` — `{"error":"not_found","message":"no such tenant"}`
- `409` — the default tenant cannot be deleted:
  `{"error":"conflict","message":"the default tenant \"default\" cannot be deleted"}`

## 11. Notes for client implementers

1. **Session:** `POST /api/admin/auth/login` → store `token` and `expires_at`. On any
   `401`, drop the token and return to the login screen; the reason in `message`
   (`expired` / `invalid`) is enough to tell the cases apart.
2. **Mode detection:** call `GET /` at startup — use `mode` and `routes` to conditionally
   render the tenant menu. In single-tenant mode, sending `X-Tenant-ID` has no effect.
3. **Switching tenants:** only add the `X-Tenant-ID` header when `role == "superadmin"`;
   sending it as `admin` gets you a `403`.
4. **Showing the token:** the `token` in the `POST /appliances` and `/rotate` responses is
   one-time — show it in a modal, confirm the copy, and do not keep it in state.
5. **Normalization:** because domain lists are sorted and deduplicated server-side, the
   `domains` returned by `PUT`/`POST` may differ from what you sent; update UI state from
   the response, not from your request.
6. **Do not send unknown fields:** the decoder is strict, and one extra field fails the
   whole request with `400`. For example, do not add `id` or `updated_at` to a `PUT` body.
7. **Caching:** the dashboard does not use `GET /api/policies` (that is the appliance
   plane); use `GET /api/admin/policies` for listing and compare the `revision` field when
   polling.
